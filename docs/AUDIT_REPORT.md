# AUDIT REPORT: Mentis ClassWiz Calculator (Casio fx-991EX Emulator)

## Section A: Root Cause Analysis of Teacher's "Math ERROR"
The teacher experienced a `Math ERROR` on release v0.1 when double-clicking `RUN_CALCULATOR.bat` on Windows.

### Primary Candidate Causes (Parser & Evaluator Defects in v0.1)
1. **Adjacent Bracket Syntax Rejection (PROVEN in v0.1)**:
   - Inputs such as `(1+2)(3+4)`, `2(3+4)(5-1)`, and `(2)(3)` produced `Math ERROR` in release v0.1 across both browser and server parsers.
2. **Exponent Operator Base Extraction Bug (PROVEN in v0.1)**:
   - `(-2)^2` and `2(3+4)^2` produced `Math ERROR` on the browser evaluator due to corrupted parenthesis tokens generated by `insertPower`.
3. **Implicit Multiplication Precedence Difference (PROVEN in v0.1)**:
   - `8÷2(2+2)` evaluated as `16` instead of `1` (Casio standard), causing unexpected calculation results.
4. **Swallowed System Exceptions (PROVEN in v0.1)**:
   - Non-math failures (network, missing assets, port conflicts) were caught by blanket `catch` blocks and displayed on the LCD as `Math ERROR`.

## Section C: Fix Commit Summary for Specific Cases
- **Case 29 (`log(100)`)**: Fixed in `frontend.html` (`5d4e6d1`). `_transformSpecial` now parses single-argument `log(x)` using `Math.log10(x)`, matching `mvp_server.py`.
- **Case 35 (`Ans` chaining)**: Fixed in `frontend.html` (`bc690a5`). `storeCalcAnswer` updates `lastAnswer` so pressing `equals` after an operation chains from `Ans`.
- **Radical (`√`) Handling**: Fixed in `mvp_server.py` (`9a285e0`). `_translate_radicals` handles parenthesized expressions (`√(9+16)` -> `sqrt(9+16)`), bare operands (`√16` -> `sqrt(16)`), and implicit multiplication (`2√9` -> `2*sqrt(9)`).
